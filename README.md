# Smart Hub - 智能中枢 · SillyTavern 扩展

一个功能完整的 SillyTavern 第三方扩展，包含 **独立 API 连接、模型拉取、必应联网搜索、完整聊天记录读取、向量 + 重排序记忆检索** 五大功能。

## ✨ 功能特性

| 功能 | 说明 |
|---|---|
| 🔌 独立 API 连接 | 连接任意 OpenAI 兼容 API（one-api / new-api / ollama / vllm / llamacpp 等），与酒馆自带 API 完全独立，互不干扰 |
| ⟳ 拉取模型 | 一键拉取 `/v1/models` 模型列表，下拉选择 |
| 🔍 必应联网搜索 | 支持必应国际版 / 必应中国版 / DuckDuckGo 备用；手动搜索、发送时自动搜索、搜索结果注入提示词 |
| 📜 完整聊天记录 | 直接读取会话底层数据，**不受消息隐藏（灯泡）和正则隐藏/替换的影响**，支持查看抽屉、导出 TXT/JSON、AI 总结 |
| 🧠 向量 + 重排序 | 独立配置向量和 Rerank 模型，对完整聊天记录（含隐藏消息）建向量索引，生成前语义检索 + 重排注入 |

兼容酒馆助手（TavernHelper）环境与原生第三方扩展安装方式。

## 📦 安装

### 方式一：扩展管理器安装（推荐）
1. 把本目录推送到任意 Git 仓库（如 GitHub）；
2. 酒馆 → 扩展管理器（🧩）→「安装扩展」→ 粘贴仓库地址 → 安装；
3. 在扩展设置中找到「Smart Hub - 智能中枢」。

### 方式二：本地安装
```bash
# 复制到 SillyTavern 的第三方扩展目录
cp -r sillytavern-smart-ext /path/to/SillyTavern/public/scripts/extensions/third-party/
# 重启酒馆或在扩展管理器中重新加载即可
```

## 🚀 使用步骤

### 1. 启动搜索桥接服务（必应搜索需要）
浏览器无法直连必应（CORS 限制），需在本地或服务器运行桥接服务（零依赖，Node 18+）：

```bash
cd bridge
node server.mjs
# 输出：Smart Hub 搜索桥接服务已启动: http://127.0.0.1:5123
```

### 2. 配置扩展
打开扩展设置页「Smart Hub - 智能中枢」，共 4 个标签页：

- **🔌 API 连接**：填写 API 地址与密钥 → 拉取模型列表 → 选择模型 → 测试连接
- **🔍 联网搜索**：搜索接口填 `http://127.0.0.1:5123/search`，选择必应引擎，可勾选「发送消息时自动搜索」
- **🧠 向量记忆**：填入向量 API / 模型（如 `text-embedding-3-small`、`bge-m3`），可选填 Rerank API / 模型（如 `bge-reranker-v2-m3`），勾选启用
- **📜 聊天记录**：查看 / 导出完整记录（含隐藏消息），或让 AI 读取全部记录并总结

## ⌨️ 快捷指令与按钮

- `/sh搜索 关键词` — 必应搜索并弹出结果浮层
- `/shweb 关键词` — 必应搜索并把结果注入提示词
- `/sh聊天记录` — 打开完整聊天记录查看器
- 输入框旁的 🔍 快捷按钮 — 快速搜索输入框内容

## 🔒 为什么聊天记录读取不受隐藏影响？

- 「隐藏消息」（灯泡）只是给消息标记 `is_system`，**前端不渲染**，但底层数据仍在会话数组中；
- 正则扩展的隐藏/替换只作用于**展示层与发送层**，不修改原始消息数据。

本扩展直接读取底层数据数组，因此拿到的永远是完整、未删改的记录。被隐藏的消息在查看器中以红色标注。

## ❓ 常见问题

- **搜索报 CORS 错误** → 未启动 bridge 服务，或搜索接口地址填错。
- **拉取模型 401/403** → API 密钥错误；部分本地服务可留空密钥。
- **向量索引失败** → 确认向量模型名正确且 API 支持 `/v1/embeddings`；Rerank 需 API 支持 `/v1/rerank`（Jina / SiliconFlow / 本地 xllamaproxy 等均支持）。
- **桥接服务部署在远程** → 修改 `server.mjs` 中 PORT 并保证 HTTPS 或局域网可达即可，扩展端填对应地址。
